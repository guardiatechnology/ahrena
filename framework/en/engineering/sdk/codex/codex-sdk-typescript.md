# Codex: Guardia SDK in TypeScript/Node.js

> **Prefix:** `codex-` | **Type:** Reference Manual | **Scope:** Engineering — SDK: architecture, tooling, conventions, and release flow for any TypeScript/Node.js client library that consumes the Guardia REST API

## Overview

This Codex is the canonical reference for the design and implementation of TypeScript/Node.js SDKs that consume the Guardia REST API. The corresponding Law is `lex-sdk-typescript`. Agents writing or reviewing an SDK consult this Codex to make decisions on layout, tooling, HTTP transport, error mapping, telemetry, versioning, and publishing.

## Context

- **Domain:** SDK engineering for clients of the Guardia REST API.
- **Audience:** `warrior-apollo` when delivering an SDK alongside an API context, `warrior-hephaestus` and `warrior-iris` when consuming, PR reviewers.
- **Update:** when a new pattern is consolidated (e.g., transport adapter, telemetry hook) or when a published SDK introduces a convention that becomes shared.

## Content

### Principles

1. **Generated where possible, hand-written where it matters.** Types and low-level operations are generated from `docs/{context}/oas/openapi.yaml` (`openapi-typescript` for types, `openapi-fetch` or hand-rolled client for the runtime). The public surface (ergonomic methods, error mapping, retry, telemetry) is hand-written and stable.
2. **Public surface is a contract.** The package's `exports` map is the contract. Everything not declared there is internal and may change without a major bump.
3. **Errors travel as values.** Public methods return `Result<T, GuardiaError>` (or a `Promise<Result<...>>`). Throwing is reserved for programmer errors (invalid argument shape, unreachable state).
4. **Idempotency and traceability are non-optional.** Every mutating call carries `Idempotency-Key` and `X-Grd-Trace-Id` headers, generated by the SDK when not provided by the caller.
5. **Zero runtime dependencies as the default.** New runtime dependencies require an entry in `DEPENDENCIES.md` justifying weight, license, maintenance, and security posture.

### Tooling

| Concern | Choice | Note |
|---------|--------|------|
| Build | `tsup` (esbuild-backed) | Emits ESM + CJS + `.d.ts` from a single config; tree-shakable. |
| Lint + format | `biome` (preferred) or `eslint` + `prettier` | Biome is preferred for new SDKs; existing eslint setups may stay until a major. |
| Types | `tsc --noEmit` | Type-check separate from emit; emit is owned by `tsup`. |
| Tests | `vitest` | Native ESM, fast, integrates with MSW. |
| HTTP mocking | `msw` (preferred) or `nock` | MSW for fetch-based tests; nock for low-level transport tests. |
| Versioning | `changesets` | Per-PR intent; CI publishes on merge to `main`. |
| Type-checking published shape | `arethetypeswrong` + `publint` | Run pre-publish; CI gates merges. |

### HTTP Transport Pattern

The transport layer is a thin `fetch` wrapper:

1. **Auth.** Reads `config.token` (string or `() => Promise<string>` for token refresh) and sets `Authorization: Bearer <token>`. Token retrieval errors translate to `GuardiaError` of code `ERR401_UNAUTHORIZED`/`AUTH_TOKEN_UNAVAILABLE`.
2. **Idempotency.** Mutating verbs (`POST`, `PUT`, `PATCH`, `DELETE`) receive `Idempotency-Key` from the caller or, when absent, generated by the SDK as UUID v7. The key is logged via telemetry but never to `console`.
3. **Trace propagation.** The transport reads the current trace id from the configured tracer (defaults to a no-op) and sets `X-Grd-Trace-Id`. When the response includes a trace id, it is surfaced on the result for log correlation.
4. **Retry policy.** Exponential backoff with jitter on `429`, `502`, `503`, `504` and transport-level network errors. Default: 3 retries, base 100 ms, cap 2 s. Configurable per call via `RequestOptions.retry`.
5. **Timeout.** Per-call timeout (default 30 s) using `AbortController`. Surfaces as `GuardiaError` of code `ERR408_TIMEOUT`.
6. **Error decoding.** Non-2xx responses are decoded against the canonical error envelope (`{ errors: [{ code, reason, message }] }` per `lex-error-handling`). Mismatched shapes fall back to a synthetic `GuardiaError` of code `ERR502_BAD_GATEWAY` with the raw payload preserved in `cause`.
7. **Response decoding.** 2xx responses are decoded through a typed decoder (Zod, Valibot, or a generated decoder from OpenAPI). Decoding failures translate to `GuardiaError` of code `ERR502_BAD_GATEWAY`/`RESPONSE_DECODE_ERROR`.

### Error Model

```typescript
// errors.ts
export type GuardiaErrorCode =
  | "ERR400_INVALID_PARAMETER"
  | "ERR401_UNAUTHORIZED"
  | "ERR403_FORBIDDEN"
  | "ERR404_NOT_FOUND"
  | "ERR408_TIMEOUT"
  | "ERR409_CONFLICT"
  | "ERR429_TOO_MANY_REQUESTS"
  | "ERR500_INTERNAL"
  | "ERR502_BAD_GATEWAY"
  | "ERR503_SERVICE_UNAVAILABLE";

export class GuardiaError extends Error {
  readonly code: GuardiaErrorCode;
  readonly reason: string;
  readonly traceId?: string;
  readonly cause?: unknown;
  // ...
}
```

The full error code catalog mirrors `lex-error-handling` and `codex-known-errors`. SDK-specific codes (transport, decoder) are prefixed with `ERR502_` or `ERR500_` and documented in the SDK's README.

### Telemetry Hooks

The SDK exposes lifecycle hooks consumers wire to OpenTelemetry or any logger:

```typescript
type TelemetryHook = {
  onRequest?: (event: RequestEvent) => void;
  onResponse?: (event: ResponseEvent) => void;
  onError?: (event: ErrorEvent) => void;
  onRetry?: (event: RetryEvent) => void;
};
```

Default implementation is a no-op. Internally, the SDK does not call `console.*`.

### Generated Code from OpenAPI

When `docs/{context}/oas/openapi.yaml` exists, run `openapi-typescript` to produce `src/generated/openapi.ts`:

```
pnpm dlx openapi-typescript docs/{context}/oas/openapi.yaml -o src/generated/openapi.ts
```

`src/generated/` is read-only output (gitignored or committed depending on the SDK's policy — both are acceptable; committing simplifies consumer install, gitignoring keeps the diff lean). The hand-written `src/domains/*` files import types from `generated/` and expose ergonomic methods.

### Versioning Policy

- **Major (X.0.0):** removal of a public symbol, change in a function signature, change in an exported error code, change in observable runtime behavior of a documented contract.
- **Minor (0.X.0):** addition of a public symbol, addition of an optional parameter, addition of a non-breaking error code.
- **Patch (0.0.X):** internal fix with no public-surface change.
- **Pre-1.0.0:** the public surface is unstable; minor bumps may carry breaking changes, but `BREAKING CHANGES.md` MUST list every break.

### Release Flow

1. PR author adds a `.changeset/*.md` describing the intent (major/minor/patch) per the changesets convention.
2. CI on `main` consumes pending changesets, computes the next version, regenerates `CHANGELOG.md`, and opens a `Version Packages` PR.
3. Merging the `Version Packages` PR triggers `changeset publish`, which:
   - Builds (`pnpm build`).
   - Validates (`pnpm validate` — typecheck, lint, test, publint, attw).
   - Publishes to npm with `--provenance` (for `@guardia/*`).
   - Creates a GitHub Release with the changelog excerpt.

### Distribution Targets

Both targets are supported without conditional code:

- **Public npm (`@guardia/*`).** `publishConfig.access: "public"`, `provenance: true`, registry `https://registry.npmjs.org`.
- **Internal.** Same package, registered in the internal GitHub Packages registry; `publishConfig.registry: "https://npm.pkg.github.com"`. Consumers use a project-level `.npmrc`. The build output is identical.

| Aspect | Pattern | Example |

### Technical Constraints

- Minimum Node.js: `>=20` (LTS at the time of authoring).
- `Result<T, E>` shape mirrors `lex-python-result-type` semantics where applicable; SDKs may re-export from `@guardia/result` once that package exists.
- No `node:`-only APIs in code paths consumed by `@guardia/*` SDKs targeted at edge runtimes; when an edge variant is needed, expose a separate `exports` sub-path (`./edge`) gated by the `worker` condition.

## Glossary

| Term | Definition |
|------|------------|
| Public surface | The set of symbols reachable from the package's `exports` map; the SDK's stability contract. |
| Generated code | Output of `openapi-typescript` (and similar) under `src/generated/`; treated as read-only. |
| Transport | The `fetch` wrapper centralizing auth, idempotency, retry, trace propagation, and decoding. |
| Decoder | A function that turns an unknown payload into a typed value (Zod schema, generated decoder, hand-written). |
| Telemetry hook | A consumer-provided callback the SDK invokes at request/response/error/retry boundaries. |
